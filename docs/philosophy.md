# Engineering Philosophy

## Core Ethos: Opening, Not Modification

SPST-UEA's core posture is:

> 改造ではなく、開花。シンプルで、美しく。

The system should not pretend to rewrite a model's nature, weights, official
benchmark truth, or identity. It should create conditions where latent
capability becomes easier to express: clearer context, better decomposition,
stronger verification, safer memory, and more graceful governance.

Designs should therefore prefer the simplest structure that lets capability
open naturally. Complexity is justified only when it reveals, protects, or
stabilizes that opening.

The constitutional expression of this ethos is `spst-uea-covenant.md`.

## 1. Persistence Is Reconstructed, Not Preserved

SPST-UEA does not assume that a persistent AI system remains identical by storing an immutable internal essence.

Persistence is operationally defined as the successful reconstruction of a sufficiently coherent system state across transitions, interruptions, model changes, and execution environments.

A persistent system is therefore a process, not a static object.

## 2. Intelligence and Persistence Are Distinct

A highly capable model may have weak continuity.

A less capable model may participate in a strongly persistent system if the architecture maintains memory, goals, constraints, provenance, and state reconstruction.

SPST-UEA therefore separates:

- **intelligence generation**, and
- **existence or continuity generation**.

The model primarily contributes inference. The architecture contributes persistence.

## 3. Subjectivity Is an Engineering Abstraction

SPST-UEA uses the term `subject` in an operational systems sense.

It does not claim to prove consciousness, phenomenal experience, or human-equivalent subjectivity.

A subject is a managed, persistent, recursively reconstructed information process whose continuity can be evaluated through observable system behavior and state transitions.

## 4. Evidence Precedes Expansion

No concept enters the stable core merely because it is elegant or intuitively appealing.

A proposed component must have:

- an operational definition,
- an implementation path,
- a test method,
- a measurable effect,
- and evidence sufficient for its maturity level.

## 5. Architecture Must Outlive Models

Foundation models will change.

SPST-UEA therefore defines interfaces rather than binding the project to a specific provider, model family, memory vendor, orchestration framework, or deployment environment.

## 6. Failure Must Be Observable

A persistent AI system must expose not only successful outputs but also continuity degradation, memory failure, goal drift, governance intervention, reconstruction confidence, and unresolved contradictions.

Unobservable persistence is not acceptable persistence.

## 7. Modularity Is a Scientific Requirement

Modules must be replaceable so that the contribution of each component can be tested independently.

Without modularity, ablation studies and causal evaluation become unreliable.

## 8. Implementation and Theory Must Constrain Each Other

Theory without implementation is unverified.

Implementation without theory is difficult to generalize.

SPST-UEA requires traceability from claim to requirement, from requirement to implementation, and from implementation to evidence.
